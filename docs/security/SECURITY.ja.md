# セキュリティポリシー

[English](../../SECURITY.md) · [Français](SECURITY.fr.md) · [中文](SECURITY.zh.md) · [हिन्दी](SECURITY.hi.md) · [Español](SECURITY.es.md) · [العربية](SECURITY.ar.md) · [বাংলা](SECURITY.bn.md) · [Português](SECURITY.pt.md) · [Русский](SECURITY.ru.md) · **日本語**

Hypercom は少人数のチームによって、専業の体制の外側で維持されている。
このドキュメントは、それが何を意味するかを正直に述べる。

## 脆弱性の報告

**セキュリティの脆弱性については、公開の issue を立てないこと。**
このリポジトリの
[GitHub の非公開脆弱性報告](../../../../security/advisories/new)
機能を使うこと(*Security* タブ → *Report a vulnerability*)。修正が
公開されるまで、報告はメンテナーにしか見えない。

以下を記述する:

- 可能であれば、関係するファイルと関数;
- 問題を再現するための正確な条件;
- 具体的な影響(「なんとなく怪しい」ではなく、攻撃者が何を得るか)。

## 対象範囲

[docs/THREAT_MODEL.md](../THREAT_MODEL.md) に列挙された保証のいずれか
を偽にしてしまう欠陥すべて――例えば、受信者の鍵なしに読める DM、
署名による認証の回避、SQL インジェクション、認証なしにリモートから
引き起こせるクラッシュ、メモリからの秘密情報の漏洩。

## 脆弱性ではないもの

`THREAT_MODEL.md` が記録しているのは**受け入れた**上での制限であり、
見落としではない。サーバーは誰が誰に書き込んでいるかを把握できる
こと、「友達限定」は暗号化ではないこと、悪意あるサーバー運営者は
自分のユーザーに嘘をつける可能性があること。こうした特定の論点への
報告は、バグとしてではなく、このドキュメントを示すことでクローズ
される。

## 対象バージョン

Hypercom にはまだ番号付きの安定版リリースがない。セキュリティ修正を
受け取るのは `main` ブランチのみ。

## 対応時間

正式な SLA はない――これは二人だけのプロジェクトであり、企業では
ない。実際には、一週間以内に受領を確認し、報告を公開する前に修正
または対応計画を伝える。
