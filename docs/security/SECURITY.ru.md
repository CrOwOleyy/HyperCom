# Политика безопасности

[English](../../SECURITY.md) · [Français](SECURITY.fr.md) · [中文](SECURITY.zh.md) · [हिन्दी](SECURITY.hi.md) · [Español](SECURITY.es.md) · [العربية](SECURITY.ar.md) · [বাংলা](SECURITY.bn.md) · [Português](SECURITY.pt.md) · **Русский** · [日本語](SECURITY.ja.md)

Hypercom поддерживается небольшой командой, вне какой-либо
профессиональной структуры. Этот документ честно говорит, что это
означает.

## Как сообщить об уязвимости

**Не открывайте публичный issue для уязвимости безопасности.**
Используйте [приватное сообщение об уязвимостях GitHub](../../../../security/advisories/new)
этого репозитория (вкладка *Security* → *Report a vulnerability*): отчёт
виден только сопровождающим до тех пор, пока не выпущено исправление.

Опишите:

- затронутый файл и функцию, если возможно;
- точные условия для воспроизведения проблемы;
- конкретное воздействие (что получает атакующий, а не просто «выглядит
  подозрительно»).

## Что входит в область применения

Любая уязвимость, делающая ложной одну из гарантий, перечисленных в
[docs/THREAT_MODEL.md](../THREAT_MODEL.md) — например: личное сообщение,
читаемое без ключа получателя, обход аутентификации на основе подписи,
SQL-инъекция, удалённо вызываемый сбой без аутентификации, утечка
секрета через память.

## Что не является уязвимостью

`THREAT_MODEL.md` документирует **принятые** ограничения, а не
недосмотры: сервер видит, кто кому пишет, «только для друзей» — это не
шифрование, злонамеренный оператор сервера может лгать собственным
пользователям. Сообщения об этих конкретных моментах будут закрыты со
ссылкой на этот документ, а не рассмотрены как баг.

## Поддерживаемые версии

У Hypercom пока нет пронумерованного стабильного релиза: исправления
безопасности получает только ветка `main`.

## Время ответа

Никакого формального SLA — это проект двух человек, а не компания. На
практике: подтверждение получения в течение недели, исправление или
план действий сообщается до публичного раскрытия отчёта.
